# 펀치리스트 (결함 추적) — ruya 시운전

> 시운전 중 발견된 결함·미비사항을 추적합니다. 한 건이 종결될 때까지 **상태를 계속 갱신**하세요. ID는 `P-0001` 처럼 일련번호로 부여합니다.
>
> **관리 역할:** 펀치리스트는 **엔지니어링**이 등록·추적·종결을 관리하고, **테크니션**이 현장에서 이상을 발견해 1차 보고(제기)합니다. 담당 역할 예시는 통상 **엔지니어링**(설계·기술 조치)입니다.

## 심각도 기준

| 심각도 | 의미 | 처리 원칙 |
| --- | --- | --- |
| **치명 (Critical)** | 안전·운전 불가, 게이트 통과 불가 사유 | 즉시 조치, 종결 전 Go 불가 |
| **중 (Major)** | 성능·일정에 영향, 기능 제한 | 기한 내 조치, 조건부 Go 가능 |
| **경 (Minor)** | 경미한 외관·편의 사항 | 인수 전까지 정리 |

## 상태 값

`open` (제기됨) → `in-progress` (조치 중) → `verify` (조치 완료, 확인 대기) → `closed` (종결)

## 운영 규칙

- 펀치 1건 = `#ruya-이슈펀치` 스레드 1개. 조치 사진·근거는 스레드에 남깁니다.
- **치명(Critical) 펀치가 하나라도 open이면 해당 게이트는 No-Go** 입니다. ([go-no-go-체크리스트.md](../go-no-go-체크리스트.md) 연동)
- `verify → closed` 전환은 **엔지니어링(펀치 관리)** 이 제기자(테크니션 등) 확인을 거쳐 처리합니다.
- 종결 시 종결일·확인자를 반드시 기록합니다.
