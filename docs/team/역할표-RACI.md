# 역할표 — RACI (ruya 시운전)

> 3개 역할 × 주요 시운전 업무의 책임 분담표입니다. 역할은 확정되었으며(테크니션 / 슈퍼바이저 / 엔지니어링), 담당자 이름·연락처만 `〈...〉` 플레이스홀더로 두었습니다.

## 역할 정의 (확정)

| 역할 | 영문 | 핵심 책임 |
| --- | --- | --- |
| **테크니션** | Technician | 현장 시운전 실행 — 장비 조작, 시험 수행, 현장 점검·측정, 이상 발견 및 1차 보고 |
| **슈퍼바이저** | Supervisor | 테크니션 서포트 및 조직 간 중간다리 — 일정 조율, 안전 관리, 커뮤니케이션 허브, 일일보고 취합, Go/No-Go 판정 진행 주관 |
| **엔지니어링** | Engineering | 펀치리스트 관리 + 설계(디자인) — 결함 등록·추적·종결, 설계 검토/변경, 기술 판정 근거 제공 |

## RACI 표기

| 기호 | 의미 | 설명 |
| --- | --- | --- |
| **R** | Responsible (실행) | 실제로 일을 수행하는 주체 (여러 역할 가능) |
| **A** | Accountable (최종책임) | 결과를 책임지고 승인하는 주체 (**업무당 1개 역할만**) |
| **C** | Consulted (협의) | 수행 전/중에 의견을 묻는 주체 |
| **I** | Informed (보고) | 결과를 통보받는 주체 |

> `R/A` 는 "그 역할이 수행하면서 최종책임도 진다"는 뜻입니다.

## 주요 업무 RACI

| 업무 | 테크니션 | 슈퍼바이저 | 엔지니어링 |
| --- | --- | --- | --- |
| 시험절차서 검토·승인 | C | I | **R/A** |
| 일일 시운전 실행 (장비 조작·시험 수행) | **R** | **A** | C |
| 현장 점검·측정·이상 1차 보고 | **R** | **A** | I |
| 펀치리스트 작성·추적·종결 | C | I | **R/A** |
| 설계 검토·변경·디자인 | I | I | **R/A** |
| 안전 관리·LOTO/작업허가(PTW) | R | **R/A** | I |
| 일일보고 작성·취합 | C | **R/A** | I |
| 조직 간 조율·소통 (커뮤니케이션 허브) | I | **R/A** | C |
| 일정 조율 | I | **R/A** | C |
| 게이트 Go/No-Go 판정 진행(주관) | C | **R/A** | C |
| 게이트 기술 판정(근거 제공) | I | C | **R/A** |
| 게이트 현장 확인 | **R** | **A** | C |

> **역할 요약:** 현장 실행·현장 확인은 **테크니션(R)**, 조율·안전·보고·게이트 진행 주관은 **슈퍼바이저(R/A)**, 펀치·설계·기술 판정은 **엔지니어링(R/A)** 이 책임집니다.

> **주의:** 각 행에 **A(최종책임)는 1개 역할만** 두는 것이 원칙입니다. 업무가 추가되면 이 표에 행을 추가하고, 반드시 A를 한 곳으로 지정합니다.

## 담당자 지정 (연락처)

| 역할 | 담당자 | 연락처 | 비고 |
| --- | --- | --- | --- |
| 테크니션 | 〈이름〉 | 〈연락처〉 | 현장 시운전 실행 |
| 슈퍼바이저 | 〈이름〉 | 〈연락처〉 | 주관·안전·커뮤니케이션 허브 |
| 엔지니어링 | 〈이름〉 | 〈연락처〉 | 펀치·설계·기술 판정 |

> 역할별 인원이 여러 명이면 행을 추가하되, 각 역할의 **대표 1명(판정 서명자)** 을 명시하세요.

## 사용 규칙

- 분쟁이 생기면 해당 업무의 **A 역할**이 최종 결정합니다.
- 게이트 판정은 **세 역할 공동**으로 하며, 서명을 남깁니다. ([go-no-go-체크리스트.md](go-no-go-체크리스트.md))
- RACI 변경은 PR로 올려 세 역할이 합의 후 반영합니다.
