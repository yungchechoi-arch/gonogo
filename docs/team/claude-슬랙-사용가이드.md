# Slack에서 Claude 팀 사용 가이드 (ruya)

> 팀원이 Slack에서 Claude(이 봇)에게 작업을 요청하고, 결과를 **PR로 받아 리뷰**하는 방법을 설명합니다. Claude는 저장소 `yungchechoi-arch/gonogo` 에서 문서·설정 작업을 도와줍니다.

## 1. Claude가 하는 일 / 안 하는 일

| 한다 | 안 한다 |
| --- | --- |
| 문서 작성·수정(템플릿, 보고서, 체크리스트 등) | 승인 없이 `main` 에 직접 반영 |
| 저장소 구조 정리, 파일 생성/이동 | 민감정보를 외부로 전송 |
| 변경을 **브랜치 + PR** 로 올리기 | 사람 대신 최종 Go/No-Go 판정 |
| 자료 조사·정리, 표/요약 작성 | 현장 실제 계측·시험 수행 |

**중요:** Claude의 산출물은 **제안(PR)** 입니다. 머지 여부는 항상 사람이 리뷰 후 결정합니다.

## 2. 처음 한 번: 각자 Claude 계정 연결

1. 각 팀원은 본인의 Claude 계정이 필요합니다. (claude.ai)
2. Slack에서 Claude 봇과 **DM**을 열거나, 팀 Claude 채널(`#ruya-claude`, 운영 시)에서 멘션합니다.
3. 최초 사용 시 **GitHub 연결/권한 승인** 안내가 나오면 따릅니다. (저장소 접근 권한이 있어야 PR 생성 가능)
4. 연결이 막히거나 권한 오류가 나면 〈관리자/PM 이름〉 에게 요청하세요.

> 조직별로 계정 정책이 다를 수 있습니다. 연결이 안 되면 혼자 우회하지 말고 관리자에게 문의하세요.

## 3. 작업 흐름 (브랜치 → PR → 리뷰)

```
Slack에서 요청  →  Claude가 개발 브랜치에서 작업  →  PR 생성(초안)  →  팀 리뷰  →  머지
```

- **대상 저장소:** `yungchechoi-arch/gonogo`
- **작업 원칙:** Claude는 `main` 에 직접 쓰지 않고 **별도 브랜치**에서 작업한 뒤 PR을 올립니다.
- **리뷰:** PR에는 변경 요약이 담깁니다. 영향받는 조직이 내용을 확인하고 코멘트/승인합니다.
- **머지:** 리뷰가 끝나면 사람이 머지합니다. 급하지 않은 변경은 **초안(Draft) PR** 로 먼저 공유하세요.
- 커밋/PR 제목은 `docs:` `feat:` `fix:` 등 접두사를 사용합니다.

## 4. 좋은 요청 작성법

**원칙: 무엇을 / 어디에 / 어떤 형식으로 / 왜 를 담으세요.**

### 좋은 예

> "`docs/team/templates/일일시운전보고-템플릿.md` 를 기준으로 오늘(11/12) 일일보고 초안을 만들어줘. 조직 B 설치 90% 완료, 조직 C 단독시운전 2건 수행, 펀치 신규 1건(냉각수 밸브 누설). PR로 올려줘."

> "Go/No-Go 체크리스트에 '통합시운전' 게이트 항목을 3개 추가해줘: 인터락 시험, 비상정지 시험, 통신 연동 확인. 기존 표 형식 유지."

### 나쁜 예

> "보고서 좀 써줘" (무엇을? 어떤 데이터로?)
>
> "다 정리해줘" (범위 불명확)

### 요청 팁

- 기준이 될 **파일 경로**를 알려주면 형식이 일관됩니다.
- 숫자·날짜·조직명 같은 **사실값**을 함께 주세요. Claude는 현장 실데이터를 모릅니다.
- 큰 작업은 한 번에 하나씩. (예: "채널 구성안" 과 "로드맵" 은 따로 요청)

## 5. 하지 말아야 할 것 (보안·안전)

- **민감정보 입력 금지:** 개인정보(주민번호·전화·주소), 비밀번호/토큰/키, 계약 금액 등 대외비는 Slack/Claude에 올리지 마세요.
- **승인 없는 외부 전송 금지:** 데이터를 외부 서비스·이메일로 보내는 요청은 하지 마세요. 꼭 필요하면 PM 승인 후 진행합니다.
- **현장 판단을 떠넘기지 않기:** 안전·시험 합부·Go/No-Go 최종 판정은 사람이 합니다.
- **대량 자동 머지 금지:** Claude가 올린 PR도 반드시 사람이 읽고 머지합니다.
- 애매하면 `#ruya-시운전` 또는 PM에게 먼저 물어보세요.

## 6. 결과를 PR로 받아 리뷰하는 체크리스트

- [ ] PR 제목·설명이 변경 내용을 정확히 담고 있는가
- [ ] 바뀐 파일이 의도한 파일만인가 (불필요한 변경 없음)
- [ ] 수치·조직명·날짜 등 **사실값이 맞는가** (Claude가 추정했을 수 있음)
- [ ] 민감정보가 포함되지 않았는가
- [ ] 영향받는 조직이 확인했는가
- [ ] 머지 후 Slack `#ruya-공지` 또는 관련 채널에 공유했는가
