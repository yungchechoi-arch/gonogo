# Slack 채널 구성안 (ruya 시운전)

> 3개 역할(테크니션 / 슈퍼바이저 / 엔지니어링) · 10명 이내 소규모 시운전 팀을 위한 Slack 채널 구조, 명명 규칙, 운영 규칙, 온보딩 체크리스트입니다. **과하게 쪼개지 말고 아래 채널로 시작**하세요.

## 1. 명명 규칙

- 모든 채널은 `#ruya-` 접두사로 시작합니다. (프로젝트 식별용)
- 채널명은 **소문자 한글/영문 + 하이픈**. 예: `#ruya-일일보고`
- 역할별 채널이 꼭 필요하면 `#ruya-<역할명>` 처럼 역할명을 붙입니다. (단, 소규모에서는 전용 채널보다 기존 채널 내 스레드를 권장)

## 2. 채널 구조

소규모라서 공용 채널 중심으로 운영하고, 채널마다 **관리 역할**을 둡니다. 아래 **6개 채널**로 시작합니다.

| 채널명 | 목적 | 관리 역할 | 초대 |
| --- | --- | --- | --- |
| `#ruya-공지` | 전체 공지·일정 | 슈퍼바이저 | 전원 |
| `#ruya-시운전` | 현장 진행·질문·실시간 공유 | 테크니션/슈퍼바이저 | 전원 |
| `#ruya-이슈펀치` | 결함/펀치 보고·추적 | 엔지니어링 | 전원 |
| `#ruya-일일보고` | 일일 시운전 보고 취합 | 슈퍼바이저 | 전원 |
| `#ruya-안전` | 안전·LOTO·위험공유 | 슈퍼바이저 | 전원 |
| `#ruya-판정` | Go/No-Go 게이트 판정 논의 | 슈퍼바이저 주관 | 전원 |

> 10명 이하라 이 6개로 충분합니다. 더 줄이려면 `#ruya-안전` 을 `#ruya-시운전` 에 통합할 수 있습니다.

### 채널별 설명(Topic) · 고정(Pin) 메시지

채널을 만든 뒤 각 채널에 아래 **설명(Topic)** 을 입력하고, **핀(Pin) 메시지** 를 작성해 상단에 고정합니다.

**`#ruya-공지`**
- 설명: `ruya 시운전 전체 공지. 결정사항·일정은 여기에.`
- 핀:
  ```
  📌 운영 허브(Notion): https://app.notion.com/p/4168d078de708143b896de9703e98194
  공식 문서(GitHub): https://github.com/yungchechoi-arch/gonogo
  ```

**`#ruya-시운전`**
- 설명: `현장 시운전 진행 상황·질문. 테크니션 중심.`
- 핀:
  ```
  시험/점검 중 이상 발견 → 바로 #ruya-이슈펀치에 등록
  ```

**`#ruya-이슈펀치`**
- 설명: `결함·펀치 보고 및 추적. 담당: 엔지니어링.`
- 핀:
  ```
  📌 펀치리스트(Notion): https://app.notion.com/p/c332fb375eea4487b0a190ff3ecd6ac4 — 새 펀치는 여기 등록 후 링크 공유
  ```

**`#ruya-일일보고`**
- 설명: `일일 시운전 보고. 매일 종료 시 작성, 슈퍼바이저 취합.`
- 핀:
  ```
  📌 일일보고(Notion): https://app.notion.com/p/20aadab515d644eeaaa2d3474559cefc
  ```

**`#ruya-안전`**
- 설명: `안전·LOTO·위험요소 공유. 작업 전 필독.`
- 핀:
  ```
  위험/아차사고는 즉시 공유. 심각 사항은 작업 중단 후 보고.
  ```

**`#ruya-판정`**
- 설명: `Go/No-Go 게이트 판정 논의. 슈퍼바이저 주관, 엔지니어링 기술판정.`
- 핀:
  ```
  📌 게이트 현황(Notion): https://app.notion.com/p/ca8370ae470046ba8e92dc63f5c07fca
  ```

### 만드는 순서

1. 채널 생성(+ → 채널 생성)으로 위 6개 생성
2. 각 채널 설명(Topic) 입력
3. 각 채널 핀 메시지 작성 후 고정
4. 팀원 10명 전 채널 초대(또는 `#ruya-공지` 에서 일괄 멘션)

## 3. 운영 규칙

### 핀(고정) 규칙

각 채널 상단에 다음을 핀으로 고정합니다.

| 채널 | 고정할 것 |
| --- | --- |
| `#ruya-공지` | 전체 일정표, 비상연락망, 현장 출입 안내 |
| `#ruya-시운전` | 로드맵 링크, 금주 목표 |
| `#ruya-일일보고` | 일일보고 템플릿 링크 |
| `#ruya-이슈펀치` | 펀치리스트(또는 링크), 심각도 기준 |
| `#ruya-안전` | 비상대응 절차, 작업허가 양식 |
| `#ruya-판정` | Go/No-Go 체크리스트 링크 |

### 스레드 사용

- **답변·토론은 반드시 스레드**에서. 채널 본문은 "새 주제 1건 = 메시지 1건".
- 일일보고/펀치/판정은 **항목 1건 = 스레드 1개**로 관리해 이력이 흩어지지 않게 합니다.
- 중요한 결론은 스레드 안에만 두지 말고 `또한 채널에도 전송` 하거나 핀으로 올립니다.

### 알림 규칙 (각자 설정)

| 채널 | 권장 알림 |
| --- | --- |
| `#ruya-공지`, `#ruya-안전`, `#ruya-판정` | 전체 메시지 알림 |
| `#ruya-시운전`, `#ruya-이슈펀치` | @멘션·키워드 알림 |
| `#ruya-일일보고` | 하이라이트만 |

- `@here` 는 지금 당장 볼 사람에게, `@channel` 은 전원이 반드시 봐야 할 때만.
- 현장 근무시간 외 알림은 안전/긴급 건에 한합니다. (팀 합의로 시간대 정하기: 〈예: 07:00~19:00〉)

- 채널 생성/권한 관리: **슈퍼바이저**(또는 워크스페이스 관리자) — 〈이름〉

- 엔지니어링 전용 공간이 필요하면 별도 채널 대신 `#ruya-이슈펀치` 안의 스레드로 운영합니다. (선택)
